## Урок 1. Введение. Первая программа. Ввод-вывод. Типы

### 1.1. Из чего состоит программа на C++?

Из директив препроцессора (`#include`), объявлений и **функции `main`** —
точки входа.

```cpp
#include <iostream>
int main() {
    std::cout << "Hello\n";
    return 0;
}
```

### 1.2. Зачем `#include <iostream>`?

Подключает заголовок для ввода-вывода (`std::cout`, `std::cin`).
Без него — ошибка компиляции.

### 1.3. Что означает `return 0;` в `main`?

Код возврата операционной системе. `0` — успех, ненулевое — ошибка.

### 1.4. Чем `\n` отличается от `std::endl`?

- `\n` — просто перевод строки.
- `std::endl` — перевод строки **+ сброс буфера**.

`\n` быстрее, `std::endl` нужен, когда важно гарантировать вывод (например, перед падением).

### 1.5. Чем `std::cin >>` отличается от `std::getline`?

- `std::cin >> s` — читает **до пробела**.
- `std::getline(std::cin, s)` — читает **всю строку** до Enter.

После `cin >> x` перед `getline` нужен `std::cin.ignore();`.

### 1.6. Основные типы данных?

`bool`, `char`, `short`, `int`, `long long` — целые.
`float`, `double` — вещественные.
`std::string` — строка (из `<string>`).

### 1.7. Что такое список инициализации переменной?

```cpp
int x{5};      // списковая — рекомендуется
int y = 5;     // копирующая
```

Списковая **запрещает сужающие преобразования**: `int x{3.14};` — ошибка.

### 1.8. Что делает `auto`?

Выводит тип из инициализатора. `auto x = 5;` → `int`.

## Урок 2. Память, IEEE 754, битовые операции

### 2.1. Что такое `sizeof`?

Оператор, возвращающий **размер типа или переменной** в байтах.
`sizeof(int)` — обычно 4.

### 2.2. Что такое IEEE 754?

Стандарт хранения вещественных чисел. `float` — 32 бита, `double` — 64.
Состоит из знака, экспоненты и мантиссы.

### 2.3. Почему `0.1 + 0.2 != 0.3`?

Числа `0.1` и `0.2` в двоичной системе — бесконечные дроби, хранятся
**приближённо**. Результат — `0.30000000000000004`.

### 2.4. Как правильно сравнивать `double`?

С точностью: `std::fabs(a - b) < eps`, где `eps` — например, `1e-9`.
Прямое `a == b` — плохо.

### 2.5. Что такое знаковые и беззнаковые типы?

- **Знаковые** (`int`) — могут быть отрицательными.
- **Беззнаковые** (`unsigned int`) — только ≥ 0.

При переполнении `unsigned` — циклический переход. Знаковый — UB.

### 2.6. Основные битовые операции?

| Операция | Знак |
|---|---|
| И | `&` |
| Или | `\|` |
| Исключающее или | `^` |
| Не | `~` |
| Сдвиг влево | `<<` |
| Сдвиг вправо | `>>` |

### 2.7. Что делает `1 << n`?

Умножение на 2ⁿ. `1 << 4` = 16.

### 2.8. Как проверить, установлен ли бит?

`(x >> pos) & 1u` — или `x & (1u << pos)`.

## Урок 3. Условия, switch, циклы

### 3.1. Чем `=` отличается от `==`?

- `=` — присваивание.
- `==` — сравнение.

`if (x = 5)` — присвоит и всегда истина. Классическая ошибка.

### 3.2. Когда использовать `switch`?

Когда сравниваем **одно значение** с несколькими **константами**.
Для диапазонов и логических условий — `if`.

### 3.3. Зачем `break` в `switch`?

Без него выполнение **проваливается** в следующий `case` (fall-through).
Обычно нужен, но иногда используется намеренно.

### 3.4. Три вида циклов?

- `while` — проверка **до** тела, может не выполниться.
- `do-while` — проверка **после**, минимум одно выполнение.
- `for` — счётчик.

### 3.5. Что делают `break` и `continue`?

- `break` — **выход** из цикла.
- `continue` — **переход к следующей итерации**.

### 3.6. Что такое range-based `for`?

```cpp
for (int x : v) { ... }
```

Обход всех элементов контейнера. По ссылке — для изменения:
`for (int& x : v)`.

## Урок 4. Функции. Рекурсия. Перегрузка

### 4.1. Что такое прототип функции?

**Объявление** до использования. Нужен, если функция используется
раньше определения.

```cpp
int add(int a, int b);   // прототип
```

### 4.2. Передача по значению vs по ссылке?

- **По значению** — копия, изменения не видны снаружи.
- **По ссылке `&`** — изменения в оригинале.
- **По `const&`** — без копии, без изменений.

**Правило:** по умолчанию — `const&`. Меняешь — `&`.

### 4.3. Что такое параметры по умолчанию?

```cpp
int power(int base, int exp = 2);
power(5);       // exp = 2
power(2, 10);   // exp = 10
```

Идут **после** обычных параметров.

### 4.4. Что такое перегрузка функций?

Несколько функций с одним именем, но **разными параметрами**.

```cpp
int add(int, int);
double add(double, double);
```

По возвращаемому типу — **нельзя** перегружать.

### 4.5. Что такое рекурсия? Ограничения?

Функция вызывает саму себя. Нужен **базовый случай** — иначе бесконечность.
Глубина ограничена **размером стека** (~10⁵ вызовов).

### 4.6. Что такое `inline` и `constexpr`?

- `inline` — подсказка вставить тело в место вызова.
- `constexpr` — вычисляется **на этапе компиляции**.

### 4.7. Что такое перегрузка vs переопределение?

- **Перегрузка** — одно имя, разные параметры, обычно в одном классе.
- **Переопределение** — `override` виртуального метода в наследнике.

## Урок 5. Указатели. Арифметика указателей

### 5.1. Что такое указатель?

Переменная, хранящая **адрес** другой переменной.

```cpp
int x = 42;
int* p = &x;      // p хранит адрес x
*p;                // 42 — разыменование
```

### 5.2. Что делают `&` и `*`?

- `&x` — **взять адрес** x.
- `*p` — **значение по адресу** p.

Один и тот же символ в разных контекстах.

### 5.3. Что такое `nullptr`?

**Нулевой указатель.** Не указывает никуда. В C++11+ заменяет `NULL`.

```cpp
int* p = nullptr;
if (p == nullptr) { ... }
```

### 5.4. Что такое арифметика указателей?

`p + 1` сдвигает указатель на **размер типа** (не на 1 байт).
Для `int*` — на 4 байта.

```cpp
int arr[5];
int* p = arr;
*(p + 2) == arr[2];   // true
```

### 5.5. Чем `const int*` отличается от `int* const`?

- `const int* p` — **указатель на константу**. Значение нельзя менять, `p` можно.
- `int* const p` — **константный указатель**. Значение можно, `p` — нельзя.

Мнемоника: читать **справа налево**.

### 5.6. Что такое висячий указатель (dangling)?

Указатель на **освобождённую** память. Разыменование — UB.

Причины: `delete` без обнуления, указатель на локальную переменную
из функции, элемент удалённого контейнера.

### 5.7. Что такое утечка памяти?

Память выделена через `new`, но `delete` не вызван. Программа растёт
в потреблении.

**Решение:** RAII, `unique_ptr`, контейнеры.

## Урок 6. Висячие указатели, утечки. Ссылки. Умные указатели

### 6.1. Чем ссылка отличается от указателя?

- Ссылка **не может быть nullptr**.
- Ссылку **нельзя перевести** на другой объект.
- Синтаксис проще: как обычная переменная.
- Ссылка **обязана быть инициализирована**.

### 6.2. Что такое `new` и `delete`?

```cpp
int* p = new int(42);      // выделить
int* arr = new int[5];     // массив
delete p;                  // освободить
delete[] arr;              // массив
```

**Правило:** каждому `new` — свой `delete`. `new[]` — только с `delete[]`.

### 6.3. Что такое RAII?

**Resource Acquisition Is Initialization.** Ресурс захватывается
в конструкторе, освобождается в деструкторе.

Обеспечивает освобождение **даже при исключении**.

### 6.4. Зачем умные указатели?

Чтобы **не писать `delete` вручную**. RAII для памяти.
Три типа: `unique_ptr`, `shared_ptr`, `weak_ptr`.

### 6.5. Что такое `unique_ptr`?

**Единственный владелец**. Не копируется, только перемещается (`std::move`).

```cpp
auto p = std::make_unique<int>(42);
```

### 6.6. Что такое `shared_ptr`?

**Общий владелец** со счётчиком ссылок. Удаляется, когда счётчик = 0.

### 6.7. Что такое `weak_ptr`?

**Слабая ссылка.** Не увеличивает счётчик. Для наблюдения,
разрыва циклических ссылок. Доступ — через `lock()`.

## Урок 7. Массивы. vector

### 7.1. Чем C-массив отличается от `std::vector`?

- C-массив — **фиксированный** размер, знает только компилятор.
- `vector` — **динамический**, растёт сам, освобождает память автоматически.

### 7.2. Как узнать размер C-массива?

`sizeof(arr) / sizeof(arr[0])` или `std::size(arr)` (C++17).

**Не работает** для указателя — там `sizeof` вернёт размер указателя.

### 7.3. Что такое `std::array`?

Обёртка над C-массивом с методами STL: `.size()`, `.at()`, `.front()`,
`.back()`, итераторы. Размер — часть типа.

### 7.4. Основные методы `vector`?

`push_back`, `pop_back`, `size`, `empty`, `clear`, `insert`, `erase`,
`reserve`, `capacity`, `at`, `front`, `back`, `[]`.

### 7.5. Что такое `size` vs `capacity`?

- `size()` — сколько **элементов**.
- `capacity()` — сколько **влезет без перевыделения**.

`capacity` растёт **удвоением**: 1, 2, 4, 8, 16...

### 7.6. Зачем `reserve`?

Заранее выделить память под N элементов — избежать перевыделения
и копирования при `push_back`.

### 7.7. Что такое `emplace_back` vs `push_back`?

- `push_back` — принимает готовый объект.
- `emplace_back` — принимает **аргументы конструктора**, создаёт объект
  прямо в контейнере.

`emplace_back` эффективнее для сложных типов.

## Урок 8. Двумерные массивы. Строки. Файлы

### 8.1. Как объявить двумерный массив?

```cpp
int m[3][4];                                  // статический
std::vector<std::vector<int>> mat(3, std::vector<int>(4));  // динамический
```

Доступ: `m[i][j]` — строка, столбец.

### 8.2. Основные методы `std::string`?

`size()`, `length()`, `empty()`, `substr`, `find`, `replace`, `insert`,
`erase`, `clear`, `contains` (C++23). `+` — конкатенация.

### 8.3. Как перевести число в строку и обратно?

- `std::to_string(42)` → `"42"`.
- `std::stoi("42")` → `42`, `std::stod("3.14")` → `3.14`.

### 8.4. Что такое `std::ifstream` и `std::ofstream`?

Файловые потоки для **чтения** и **записи**.

```cpp
std::ifstream fin("in.txt");
std::ofstream fout("out.txt");
```

Закрываются автоматически (RAII).

### 8.5. Как читать файл построчно?

```cpp
std::string line;
while (std::getline(fin, line)) { ... }
```

### 8.6. Что такое `std::istringstream`?

Поток **из строки**. Удобно для парсинга:

```cpp
std::istringstream iss("10 20 30");
int x;
while (iss >> x) { ... }
```

## Урок 9. Структуры. enum. Введение в ООП

### 9.1. Что такое `struct`?

Пользовательский тип — набор полей. По умолчанию всё `public`.

```cpp
struct Point { int x, y; };
Point p{1, 2};
```

### 9.2. Что такое `enum` и `enum class`?

**Перечисление именованных констант.**

```cpp
enum Color { Red, Green, Blue };        // имена в общей области
enum class Status { Ok, Error };        // через Status::Ok
```

**`enum class` — рекомендуется** (нет конфликтов имён).

### 9.3. Чем `struct` отличается от `class`?

**Только доступом по умолчанию:** `struct` — `public`, `class` — `private`.

### 9.4. Что такое метод?

Функция внутри класса или структуры. Имеет доступ к полям.

### 9.5. Зачем `const`-метод?

Обещает, что метод **не меняет** объект. Можно вызывать у `const`-объектов.

### 9.6. Что такое конструктор?

Функция, вызываемая **при создании** объекта.
Имя = имя класса, без возвращаемого типа.

### 9.7. Что такое список инициализации конструктора?

```cpp
Point(int x, int y) : x_(x), y_(y) {}
```

Инициализирует поля **до** тела. Эффективнее. Обязателен для `const`-полей.

## Урок 10. Контрольная работа (демо)

### 10.1. Как эффективно решать задачи КР?

1. **Прочитать условие дважды.**
2. **Начинать с простых задач.** Баллы одинаковые.
3. **Использовать STL.** Не писать велосипеды.
4. **Тестировать на границах:** пустой ввод, один элемент, максимум.
5. **Следить за временем.**

### 10.2. Классические задачи КР?

- Спираль (заполнение матрицы).
- Банкомат (жадный алгоритм).
- Палиндром (два указателя).
- Решето Эратосфена.
- Two Sum (хеш-таблица).

### 10.3. Что такое `unordered_map` для Two Sum?

Хранит **значение → индекс**. За один проход находит пару за O(n):

```cpp
for (int i = 0; i < n; ++i) {
    if (seen.count(target - arr[i])) return {seen[target - arr[i]], i};
    seen[arr[i]] = i;
}
```

## Урок 11. Классы. Конструкторы, деструкторы, операторы

### 11.1. Что такое инкапсуляция?

Сокрытие внутренней реализации. Поля — `private`, доступ — через методы.

### 11.2. Уровни доступа?

- `public` — все.
- `protected` — класс + наследники.
- `private` — только класс.

### 11.3. Что такое деструктор? Когда вызывается?

`~ClassName()`. Вызывается при уничтожении: выход из области видимости,
`delete`, конец программы (для глобальных).

### 11.4. Может ли деструктор бросать исключение?

**Нет.** Деструкторы `noexcept`. Если бросит — `std::terminate`.

### 11.5. Что такое перегрузка операторов?

Определение своих действий для `+`, `==`, `<<`, `[]` и т.д.

```cpp
Vector2 operator+(const Vector2& o) const { return {x + o.x, y + o.y}; }
```

### 11.6. Почему `operator<<` — вне класса?

Левый операнд — `std::ostream`, не наш класс.

```cpp
std::ostream& operator<<(std::ostream& os, const Vector2& v);
```

### 11.7. Что такое `this`?

Указатель на текущий объект. Нужен, когда имя поля совпадает с параметром.

### 11.8. Что такое `explicit`?

Запрет неявного преобразования конструктора с одним параметром.

```cpp
explicit Meter(double v);
Meter m = 5.0;   // ошибка
Meter m(5.0);    // ок
```

## Урок 12. Передача объектов. Коллекции. Операторы

### 12.1. Как передавать объекты в функции?

- **По значению** — если нужна копия.
- **По `const&`** — если только читаем. **Основной способ.**
- **По `&`** — если меняем.
- **По `&&`** — для move-семантики.

### 12.2. Как хранить объекты в `vector`?

```cpp
std::vector<Point> v;
v.push_back({1, 2});
v.emplace_back(3, 4);
```

### 12.3. Что такое `operator[]`?

Доступ по индексу. Две версии — `const` и не-`const`.

```cpp
int& operator[](std::size_t i) { return data_[i]; }
const int& operator[](std::size_t i) const { return data_[i]; }
```

### 12.4. Что такое функтор (functor)?

Объект с `operator()`. Можно вызывать как функцию.

```cpp
struct Adder {
    int base;
    int operator()(int x) const { return base + x; }
};
```

### 12.5. Что такое `std::map`?

Ассоциативный контейнер **ключ → значение**. Отсортирован по ключу.

```cpp
std::map<std::string, int> ages;
ages["Иван"] = 25;
```

### 12.6. Что такое `std::sort`?

Сортировка диапазона. O(n log n). **Не устойчивая.**

```cpp
std::sort(v.begin(), v.end());
std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });
```

### 12.7. Что такое компаратор?

Функция сравнения. Должна быть **строгим слабым порядком**:
`cmp(a, a) == false`. Иначе UB.

**Правильно:** `a < b`. **Неправильно:** `a <= b`.

## Урок 13. Исключения. RAII. Правило пяти

### 13.1. Что такое исключение?

Объект, описывающий ошибку. `throw` — выброс, `try`/`catch` — перехват.

### 13.2. Иерархия исключений?

`std::exception` — базовый.
Наследники: `std::runtime_error`, `std::logic_error`,
`std::invalid_argument`, `std::out_of_range`, `std::bad_alloc`.

### 13.3. Порядок `catch`?

От **частных** к **общим**. `catch (...)` — последний.

### 13.4. Как поймать по ссылке?

`catch (const std::exception& e)` — **всегда по ссылке**, не по значению
(иначе срезка).

### 13.5. Зачем свои классы исключений?

Для **специфичных ошибок** бизнес-логики.
Наследуются от `std::runtime_error` или `std::exception`.

```cpp
class BankException : public std::runtime_error { ... };
```

### 13.6. Что такое RAII?

Ресурс — в конструкторе, освобождение — в деструкторе.
Работает **даже при исключении**.

### 13.7. Правило трёх / пяти / нуля?

- **Трёх:** деструктор + копирующий конструктор + копирующее присваивание.
- **Пяти:** плюс move-конструктор и move-присваивание.
- **Нуля:** если не управляешь ресурсами вручную — ничего не определяй.

### 13.8. Что такое `noexcept`?

Обещание, что функция не бросает. Компилятор оптимизирует.
**На move-операциях обязательно** — иначе `vector` будет копировать.

### 13.9. Что такое `std::expected` (C++23)?

Альтернатива исключениям для **ожидаемых** ошибок:
`std::expected<T, E>` — «или значение, или ошибка».

---

## Урок 14. Умные указатели

### 14.1. Что такое `unique_ptr`?

**Единственный владелец.** Не копируется, только `std::move`.
Освобождает память автоматически.

```cpp
auto p = std::make_unique<int>(42);
```

### 14.2. Что такое `shared_ptr`?

**Общий владелец** со счётчиком ссылок. Удаляется, когда счётчик = 0.

```cpp
auto p = std::make_shared<int>(42);
auto q = p;                    // счётчик = 2
```

### 14.3. Что такое `weak_ptr`?

**Слабая ссылка.** Не увеличивает счётчик.
Проверка живости: `expired()`. Доступ: `lock()`.

### 14.4. Что такое циклическая ссылка?

Два `shared_ptr` друг на друга → счётчики никогда не 0 → **утечка**.
Решение: одна ссылка `weak_ptr`.

### 14.5. Когда что использовать?

| Задача | Указатель |
|---|---|
| Один владелец | `unique_ptr` |
| Несколько владельцев | `shared_ptr` |
| Наблюдение без владения | `weak_ptr` |
| Просто смотрит, не владеет | `T*` или `T&` |

### 14.6. `make_unique` vs `new`?

`make_unique` — **безопаснее** (исключение не оставит память без владельца)
и короче. `make_shared` ещё и одним блоком выделяет.

### 14.7. Как хранить `unique_ptr` в `vector`?

```cpp
std::vector<std::unique_ptr<Shape>> v;
v.push_back(std::make_unique<Circle>(5));
```

Только `std::move` или `emplace_back`. Копирование запрещено.

## Урок 15. Move-семантика

### 15.1. Что такое lvalue и rvalue?

- **lvalue** — имеет имя и адрес (`x`, `arr[0]`).
- **rvalue** — временное значение (`5`, `x + y`).

### 15.2. Что такое rvalue-ссылка `T&&`?

Ссылка на **временный объект**. Основа move-семантики.

```cpp
int&& r = 5;
```

### 15.3. Что такое move-конструктор?

Забирает **ресурсы** у rvalue вместо копирования.

```cpp
Buffer(Buffer&& o) noexcept : data_(o.data_), size_(o.size_) {
    o.data_ = nullptr;
    o.size_ = 0;
}
```

### 15.4. Что делает `std::move`?

**Ничего не двигает.** Приводит lvalue к rvalue-ссылке —
**разрешает** move.

После `std::move(x)` объект `x` — в «перемещённом состоянии».

### 15.5. Почему `noexcept` на move?

`std::vector` использует move **только если он `noexcept`**. Иначе копирует.

### 15.6. Что такое NRVO и copy elision?

**Оптимизация:** компилятор строит объект прямо на месте вызова,
без copy/move. В C++17 — гарантированно для некоторых случаев.

```cpp
Buffer make() { return Buffer(100); }
Buffer b = make();   // ни copy, ни move
```

### 15.7. Что такое `std::forward`?

**Perfect forwarding** — сохраняет категорию аргумента в шаблонах.
`std::move` — всегда rvalue, `std::forward` — как было.

## Урок 16. Контейнеры: vector, deque, list

### 16.1. Чем `vector`, `deque`, `list` отличаются?

- **`vector`** — динамический массив. Быстрый доступ, добавление в конец.
- **`deque`** — двусторонняя очередь. Быстро с обоих концов.
- **`list`** — двусвязный список. Быстрые вставки в середину.

### 16.2. Что по умолчанию?

**`std::vector`.** В 90% случаев выигрывает из-за **кэш-локальности**.

### 16.3. Что такое итератор?

«Указатель» на элемент. `begin()`, `end()`, `++`, `*`.

### 16.4. Какие категории итераторов?

- **Random access** (`vector`, `deque`): `+`, `-`, `<`.
- **Bidirectional** (`list`): `++`, `--`.
- **Forward** (`forward_list`): только `++`.

### 16.5. Как удалить элементы из `vector`?

```cpp
v.erase(std::remove_if(v.begin(), v.end(), pred), v.end());

// или C++20:
std::erase_if(v, pred);
```

### 16.6. Что такое `splice` у `list`?

**Перемещение** узлов между списками **без копирования**.
То, чего нет у `vector`/`deque`.

---

## Урок 17. Контейнеры: практика

### 17.1. Как выбрать контейнер?

| Задача | Контейнер |
|---|---|
| Доступ по индексу, добавление в конец | `vector` |
| Добавление/удаление с обоих концов | `deque` |
| LIFO | `stack` или `vector` |
| FIFO | `queue` или `deque` |

### 17.2. Что такое скользящее окно?

Задача «максимум в окне размера K». Оптимум — **монотонная `deque`** за O(n).

### 17.3. Что такое топ-K?

K наибольших элементов. Способы: `sort` (O(n log n)),
`partial_sort` (O(n log K)), `nth_element` (O(n) в среднем).

## Урок 18. Ассоциативные контейнеры

### 18.1. `map` vs `unordered_map`?

- **`map`** — дерево, O(log n), отсортирован.
- **`unordered_map`** — хеш-таблица, O(1) в среднем, порядок не определён.

### 18.2. Чем опасен `m[key]`?

**Создаёт элемент**, если его нет. Для чтения — `find` или `at`.

### 18.3. Что такое `set`?

Множество уникальных элементов, **отсортировано**.

### 18.4. Что такое `multimap`?

`map`, допускающий дубликаты ключей.

### 18.5. Что нужно для `unordered_map` с пользовательским типом?

- **`operator==`** для сравнения.
- **`std::hash`** (или своя хеш-функция).

### 18.6. Что такое `contains` (C++20)?

Проверка наличия ключа. Короче, чем `find != end()`.

```cpp
if (m.contains(key)) { ... }
```

## Урок 19. Алгоритмы STL, ranges, лямбды

### 19.1. Что такое алгоритмы STL?

Готовые функции для диапазонов. Работают с любым контейнером.
Все — в `<algorithm>` и `<numeric>`.

### 19.2. Основные алгоритмы?

`find`, `find_if`, `count`, `count_if`, `all_of`, `any_of`, `none_of`,
`sort`, `stable_sort`, `partial_sort`, `nth_element`, `transform`,
`copy`, `copy_if`, `accumulate`, `iota`.

### 19.3. Что такое лямбда?

**Анонимная функция** на месте.

```cpp
auto f = [](int x) { return x * 2; };
```

### 19.4. Виды захвата в лямбдах?

- `[x]` — по значению.
- `[&x]` — по ссылке.
- `[=]` — все по значению.
- `[&]` — все по ссылке.
- `[x = 5]` — инициализация (C++14).

### 19.5. Что такое `mutable` в лямбде?

Разрешает менять захваченные **по значению** переменные.

### 19.6. Что такое ranges (C++20)?

Новый способ работы с последовательностями.

```cpp
std::ranges::sort(v);              // без begin/end

auto result = v | std::views::filter(pred)
               | std::views::transform(f)
               | std::views::take(3);
```

**Ленивые вычисления** — не копирует, не считает лишнее.

### 19.7. Почему `print_range` не принимает `const Range&`?

Views (`filter`, `transform`, `take`) **не имеют `const begin()`**.
Принимайте по `Range&` или `Range&&`.

## Урок 20. Контрольная работа (демо)

### 20.1. Как решать «уникальные и дубликаты»?

- `unordered_map<int, int>` — частоты.
- `set` — уникальные.
- `count > 1` — дубликаты.

### 20.2. Как группировать по ключу?

`std::map<K, std::vector<V>>` — ключ, вектор значений.

```cpp
std::map<std::size_t, std::vector<std::string>> groups;
groups[word.size()].push_back(word);
```

### 20.3. Как сделать многокритериальную сортировку?

Каскад условий в компараторе:

```cpp
if (a.avg != b.avg) return a.avg > b.avg;
if (a.age != b.age) return a.age < b.age;
return a.name < b.name;
```

Или кортеж: `std::tuple{-a.avg, a.age, a.name}`.

## Урок 21. Наследование: базовое

### 21.1. Что такое наследование?

Создание класса на основе другого. Отношение **«is-a»**.

```cpp
class Dog : public Animal { ... };   // Dog является Animal
```

### 21.2. Типы наследования?

- **`public`** — «is-a». **Основной случай.**
- `protected` — публичные → `protected`.
- `private` — всё → `private`.

### 21.3. Что видит наследник?

- `public` родителя — видит.
- `protected` родителя — видит.
- `private` родителя — **не видит**.

### 21.4. Порядок вызова конструкторов и деструкторов?

- **Конструкторы:** Base → Derived.
- **Деструкторы:** Derived → Base.

Симметрично, как стек.

### 21.5. Как вызвать конструктор родителя?

Через список инициализации:

```cpp
Dog(const std::string& n) : Animal(n) {}
```

### 21.6. Что такое срезка (slicing)?

Копирование наследника в переменную **базового типа** — теряется
часть наследника. **Не копируйте полиморфные объекты по значению.**

### 21.7. Наследование vs композиция?

- **«is-a»** → наследование.
- **«has-a»** → композиция (поле).

Композиция предпочтительнее без чёткого «is-a».

### 21.8. Зачем виртуальный деструктор?

Чтобы при `delete base_ptr` вызывался **деструктор наследника**.
Без него — утечка.

```cpp
class Base {
public:
    virtual ~Base() = default;
};
```

---

## Урок 22. Наследование: RTTI, касты

### 22.1. Что такое виртуальная функция?

Вызывается по **фактическому** типу объекта, а не по типу указателя.

```cpp
class Animal {
public:
    virtual std::string voice() const { return "..."; }
};
```

### 22.2. Что такое `override`?

Пометка переопределения. Компилятор проверит, что метод
действительно переопределяет виртуальный из родителя.

### 22.3. Где работает полиморфизм?

Только через **указатель или ссылку**. По значению — срезка.

### 22.4. Что такое vtable?

Таблица виртуальных методов. У полиморфного объекта — скрытый указатель
на неё. Через vtable компилятор находит нужный метод.

### 22.5. Что такое `dynamic_cast`?

Приведение вниз **с проверкой** во время выполнения.
Требует `virtual` в базовом классе.

```cpp
if (auto* d = dynamic_cast<Derived*>(base)) { ... }
```

Неудача: `nullptr` (для указателей) или `std::bad_cast` (для ссылок).

### 22.6. `static_cast` vs `dynamic_cast`?

- `static_cast` — без проверки, быстрее.
- `dynamic_cast` — с проверкой, медленнее.

### 22.7. Что такое `typeid`?

RTTI: `typeid(*p).name()` — имя типа. `typeid(*p) == typeid(Dog)` —
**точное** совпадение.

### 22.8. Что такое `final`?

Запрет наследования от класса или переопределения метода.

## Урок 23. Подготовка к коллоквиуму

### 23.1. Правило пяти — что определять?

1. Конструктор.
2. Деструктор.
3. Копирующий конструктор.
4. Копирующее присваивание.
5. Move-конструктор.
6. Move-присваивание.

### 23.2. Как реализовать копирующее присваивание?

1. Проверить самоприсваивание (`this != &o`).
2. Освободить старые ресурсы.
3. Скопировать новые.
4. Вернуть `*this`.

### 23.3. Что такое «правило нуля»?

Если класс **не управляет ресурсами вручную** — ничего не определяй.
Компилятор сгенерирует правильно.

### 23.4. Типичные ошибки?

- Не виртуальный деструктор.
- Срезка.
- Забыли `virtual` / `override`.
- Возврат ссылки на локальную переменную.
- Использование после `std::move`.

## Урок 24. Подготовка к коллоквиуму: практика

### 24.1. Что такое паттерн «Prototype»?

Виртуальный метод `clone()`, возвращающий копию объекта.

```cpp
virtual std::unique_ptr<Shape> clone() const = 0;
```

Позволяет копировать полиморфные объекты через базовый указатель.

### 24.2. Что такое паттерн «Observer»?

Издатель хранит подписчиков через `weak_ptr`. При изменении — уведомляет.

### 24.3. Что такое «Registry»?

Хранилище объектов по ключу: `unordered_map<string, unique_ptr<Shape>>`.

## Урок 25. Абстрактные классы

### 25.1. Что такое чистая виртуальная функция?

`virtual void f() = 0;` — без тела. Наследник **обязан** переопределить.

### 25.2. Что такое абстрактный класс?

Класс с хотя бы одной чистой виртуальной функцией.
**Объект создать нельзя**, указатель — можно.

### 25.3. Что если наследник не реализует все чистые функции?

Он тоже становится **абстрактным**.

### 25.4. Что такое интерфейс?

Абстрактный класс без полей и обычных методов — только чистые виртуальные.
В C++ отдельного ключевого слова нет.

### 25.5. Обязателен ли виртуальный деструктор в абстрактном классе?

**Да.** Иначе — утечка при удалении через базовый указатель.

### 25.6. Что такое чистый виртуальный деструктор?

`virtual ~Base() = 0;` с **обязательным телом** вне класса.

---

## Урок 26. Абстрактные классы: практика

### 26.1. Сколько интерфейсов может реализовать класс?

**Сколько угодно.** Множественное наследование интерфейсов разрешено.

### 26.2. Порядок базовых классов?

Обычный класс — **первым**, интерфейсы — следом.

```cpp
class User : public Entity, public ISerializable { ... };
```

### 26.3. Что такое «плагин-система»?

Основной код работает с интерфейсом. Плагины — отдельные классы,
реализующие интерфейс. Добавление нового плагина **не меняет** основной код.

### 26.4. Что такое «Chain of Responsibility»?

Запрос идёт по цепочке обработчиков. Каждый решает: обработать или передать.

## Урок 27. RTTI, касты

### 27.1. Виды кастов?

- `static_cast` — проверка на этапе компиляции.
- `dynamic_cast` — проверка во время выполнения (нужен `virtual`).
- `const_cast` — снятие `const`.
- `reinterpret_cast` — переинтерпретация битов.

### 27.2. Что НЕЛЬЗЯ делать `static_cast`?

- Снимать `const`.
- Переинтерпретировать биты.
- Проверять тип во время выполнения.

### 27.3. Что делает `const_cast`?

Снимает `const`. Если объект **изначально** был `const` — изменение
через `const_cast` = **UB**. Только для старого C-API.

### 27.4. Что такое `reinterpret_cast`?

Переинтерпретация битов. Самый опасный каст. Только для низкого уровня
(сериализация, embedded, приведение указателя к `uintptr_t`).

### 27.5. Почему C-style каст плох?

Компилятор сам выбирает между четырьмя кастами. **Непонятно из кода**,
что произошло. Легко случайно снять `const` или переинтерпретировать.

### 27.6. Что такое `type_info`?

Класс из `<typeinfo>`. `typeid(obj)` возвращает ссылку на `type_info`.
Методы: `.name()` (искажённое имя), `.hash_code()`.

### 27.7. Что такое `mutable`?

Ключевое слово для полей — можно менять в `const`-методах.
Для кэшей, счётчиков вызовов.

## Урок 28. Разбор демо экзамена

### 28.1. LRU-кэш: как реализовать за O(1)?

Комбинация:
- `unordered_map<int, iterator>` — быстрый поиск.
- `list<pair<int, int>>` — порядок использования (свежие в начале).

`get` — переместить в начало. `put` — добавить/обновить,
при переполнении удалить с конца.

### 28.2. Класс `Matrix`: как перегрузить `operator()`?

```cpp
double& operator()(std::size_t i, std::size_t j) {
    if (i >= rows_ || j >= cols_) throw std::out_of_range("index");
    return data_[i][j];
}
```

Две версии — `const` и не-`const`.

### 28.3. Undo/Redo: как реализовать?

- Два стека: `undo_stack` и `redo_stack`.
- При `insert` — текущее состояние в undo, очистка redo.
- При `undo` — переложить из undo в redo.
- При `redo` — обратно.

### 28.4. Как работает `clone()` для полиморфных объектов?

Виртуальный метод в базовом классе, каждый наследник возвращает
`std::make_unique<Self>(*this)`.

```cpp
std::unique_ptr<Shape> clone() const override {
    return std::make_unique<Circle>(*this);
}
```

## Мини-шпаргалка: ключевые правила

| Правило | Суть |
|---|---|
| RAII | Ресурс — в конструкторе, освобождение — в деструкторе |
| Правило нуля | Не управляй ресурсами вручную → используй `vector`, `unique_ptr` |
| Правило пяти | Если есть деструктор/копирование — определи все пять |
| Виртуальный деструктор | В любом полиморфном базовом классе |
| `override` | Всегда при переопределении |
| `explicit` | Конструкторы с одним параметром |
| `noexcept` | На move-операциях обязательно |
| «is-a» vs «has-a» | Наследование vs композиция |
| Компаратор | Строгий `<`, не `<=` |
| `unordered_*` | Когда порядок не важен — быстрее |
| `const&` | Способ передачи по умолчанию |
| `std::move` | Не двигает, только разрешает move |
