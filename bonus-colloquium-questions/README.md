## 1. Классы и объекты

### 1.1. Чем `struct` отличается от `class`?

Только **доступом по умолчанию**: у `struct` — `public`, у `class` — `private`.
Функционально идентичны. Стиль: `struct` — для простых «данных»,
`class` — для объектов с инкапсуляцией.

### 1.2. Что такое инкапсуляция?

Сокрытие внутренней реализации класса. Поля — `private`,
доступ — через публичные методы или свойства.

### 1.3. Уровни доступа?

- `public` — все.
- `protected` — класс + наследники.
- `private` — только сам класс.

### 1.4. Что такое `const`-метод?

Метод, не меняющий объект: `int get() const;`. Можно вызывать у `const`-объектов.

### 1.5. Зачем `explicit` у конструктора?

Запрещает неявное преобразование. `Person p = "Иван";` — ошибка,
`Person p("Иван");` — ок.

### 1.6. Что такое `this`?

Указатель на текущий объект внутри метода. Нужен, когда имя поля совпадает
с параметром, или для возврата `*this`.

### 1.7. Можно ли перегружать конструктор?

Да. Несколько конструкторов с разными параметрами — норма.
Деструктор — **только один**.

### 1.8. Что такое список инициализации?

`: x_(x), y_(y)` после заголовка конструктора. Инициализирует поля
**до** тела. Эффективнее присваивания. Обязателен для `const`-полей
и ссылок.

## 2. Конструкторы и деструкторы

### 2.1. Когда вызывается конструктор?

При создании объекта: локальная переменная, `new`, копия, временный объект.

### 2.2. Когда вызывается деструктор?

При уничтожении: выход из области видимости, `delete`, конец программы
(для глобальных/статических).

### 2.3. Порядок вызова в иерархии?

**Конструкторы:** Base → Derived.
**Деструкторы:** Derived → Base. Симметрично.

### 2.4. Когда нужен виртуальный деструктор?

Если объекты наследников удаляются через **базовый указатель**.
Без него — утечка. Правило: базовый класс в полиморфной иерархии
должен иметь `virtual ~Base() = default;`.

### 2.5. Может ли деструктор бросать исключение?

**Нет.** Деструкторы — `noexcept` по умолчанию. Если бросает — `std::terminate`.
Если очень нужно — ловить внутри и не пробрасывать.

### 2.6. Что такое делегирующий конструктор?

Конструктор, вызывающий другой конструктор того же класса:
`Point() : Point(0, 0) {}`.

### 2.7. Что такое `= default` и `= delete`?

- `= default` — «сгенерируй стандартную версию».
- `= delete` — «запрети операцию».

```cpp
MyClass() = default;
MyClass(const MyClass&) = delete;   // запрет копирования
```

## 3. Копирование и перемещение

### 3.1. Когда вызывается копирующий конструктор?

- `MyClass b = a;`
- Передача по значению.
- Возврат по значению (если не NRVO).

### 3.2. Что такое поверхностное и глубокое копирование?

- **Поверхностное** — копия указателя. Оба объекта указывают на одну память → двойное удаление.
- **Глубокое** — копия данных. **Правильно** для владеющих ресурсами классов.

### 3.3. Правило трёх / пяти / нуля?

- **Трёх:** если есть деструктор, копирующий конструктор или копирующее присваивание — нужны все три.
- **Пяти:** плюс move-конструктор и move-присваивание (C++11).
- **Нуля:** если класс не управляет ресурсами вручную — ничего не определяй.

### 3.4. Что такое move-конструктор?

Забирает ресурсы у rvalue-объекта вместо копирования.

```cpp
Buffer(Buffer&& o) noexcept : data_(o.data_), size_(o.size_) {
    o.data_ = nullptr;
    o.size_ = 0;
}
```

### 3.5. Что делает `std::move`?

**Ничего не двигает.** Приводит lvalue к rvalue-ссылке — разрешает move.
После `std::move(x)` объект `x` в «перемещённом состоянии».

### 3.6. Почему `noexcept` на move?

`std::vector` использует move только если он `noexcept`. Иначе — копирует
для «строгой гарантии исключений».

### 3.7. Что такое NRVO и copy elision?

Оптимизация: компилятор строит объект прямо на месте вызова,
без copy/move. В C++17 — гарантированно для некоторых случаев.

## 4. Наследование

### 4.1. Что такое наследование?

Создание нового класса на основе существующего. Отношение «is-a».

### 4.2. Типы наследования?

- `public` — «is-a», публичные члены остаются публичными. **Основной случай.**
- `protected` — публичные становятся `protected`. Редко.
- `private` — всё становится `private`. Редко.

### 4.3. Что видит наследник?

- `public` родителя — видит.
- `protected` родителя — видит.
- `private` родителя — **не видит**.

### 4.4. Как вызвать конструктор родителя?

Через список инициализации: `Dog() : Animal("Бим") {}`.

### 4.5. Что такое срезка (slicing)?

Копирование наследника в переменную базового типа — теряется часть
наследника и виртуальность. **Не копируйте полиморфные объекты по значению.**

### 4.6. Наследование vs композиция?

- **«is-a»** → наследование.
- **«has-a»** → композиция (поле).

Композиция предпочтительнее без чёткого «is-a».

### 4.7. Что такое `final`?

Запрет наследования от класса или переопределения метода.

```cpp
class NoDerive final {};
void f() override final;   // запрет дальнейшего переопределения
```

## 5. Полиморфизм

### 5.1. Что такое виртуальная функция?

Функция, вызываемая по **фактическому** типу объекта, а не по типу
указателя/ссылки. Объявляется через `virtual`.

### 5.2. Как работает `virtual` внутри?

Через **vtable** — таблицу виртуальных методов. У каждого полиморфного
объекта — скрытый указатель на vtable.

### 5.3. Что такое `override`?

Явная пометка переопределения. Компилятор проверит, что метод
действительно переопределяет виртуальный из родителя.

### 5.4. Где работает полиморфизм?

Только через **указатель или ссылку**. По значению — срезка.

### 5.5. Что такое чистая виртуальная функция?

`virtual void f() = 0;` — без тела. Наследник **обязан** переопределить.

### 5.6. Можно ли вызвать виртуальную функцию в конструкторе?

Да, но вызовется **версия базового класса**, а не наследника — vtable
ещё не построена. То же в деструкторе. **Плохая практика.**

### 5.7. Что такое абстрактный класс?

Класс с хотя бы одной чистой виртуальной функцией. Объект создать нельзя,
указатель — можно.

## 6. Абстрактные классы и интерфейсы

### 6.1. Чем абстрактный класс отличается от интерфейса?

В C++ — **ничем**, кроме стиля. Интерфейс — абстрактный класс без полей
и без обычных методов, только чистые виртуальные.

### 6.2. Сколько интерфейсов может реализовать класс?

**Сколько угодно.** Множественное наследование интерфейсов разрешено.

### 6.3. Обязателен ли виртуальный деструктор в абстрактном классе?

**Да.** Иначе при удалении через базовый указатель — утечка.

### 6.4. Что такое чистый виртуальный деструктор?

`virtual ~Base() = 0;` с **обязательным телом** вне класса. Делает класс
абстрактным без других чистых методов.

### 6.5. Что такое `clone()` (Prototype)?

Виртуальный метод, возвращающий копию объекта:

```cpp
virtual std::unique_ptr<Shape> clone() const = 0;
```

Позволяет копировать полиморфные объекты через базовый указатель.

## 7. Умные указатели

### 7.1. Что такое `unique_ptr`?

Единственный владелец. Не копируется, только перемещается.
Освобождает память автоматически (RAII).

### 7.2. Что такое `shared_ptr`?

Общий владелец. Счётчик ссылок: объект удаляется, когда счётчик = 0.

### 7.3. Что такое `weak_ptr`?

Слабая ссылка. Не увеличивает счётчик. Для наблюдения.
`lock()` возвращает `shared_ptr` или `nullptr`.

### 7.4. Зачем `weak_ptr`?

- Разорвать **циклические ссылки** `shared_ptr`.
- Наблюдение без владения.

### 7.5. Что такое циклическая ссылка?

Два `shared_ptr` друг на друга → счётчики никогда не 0 → утечка.
Решение — одна ссылка `weak_ptr`.

### 7.6. `make_unique` vs `new`?

`make_unique<T>(args)` — безопаснее (исключение не оставит указатель
без владельца) и короче. `make_shared` ещё и выделяет память одним блоком.

### 7.7. Можно ли `unique_ptr` поместить в `vector`?

**Да**, но только через `std::move` или `emplace_back`. `vector` хранит
владельцев.

## 8. RTTI и касты

### 8.1. Виды кастов?

- `static_cast` — проверка на этапе компиляции.
- `dynamic_cast` — проверка в runtime (нужен `virtual`).
- `const_cast` — снятие `const`.
- `reinterpret_cast` — переинтерпретация битов.

### 8.2. Когда `static_cast`, когда `dynamic_cast`?

- Вверх по иерархии — `static_cast` (безопасно).
- Вниз — `dynamic_cast` (с проверкой).
- `static_cast` вниз — только если точно уверен, иначе UB.

### 8.3. Что требует `dynamic_cast`?

Хотя бы одну виртуальную функцию в базовом классе. Иначе — ошибка
компиляции.

### 8.4. Что делает `const_cast`?

Снимает `const`. Если объект **изначально** был `const` — изменение
через `const_cast` = UB. Используется для старого C-API.

### 8.5. Что такое `typeid`?

RTTI: возвращает `type_info` объекта. `typeid(*p).name()` — имя типа
(искажённое). `typeid(*p) == typeid(Dog)` — точное совпадение.

### 8.6. Чем `typeid` отличается от `dynamic_cast`?

- `typeid` — **точное** совпадение.
- `dynamic_cast` — «является ли» (с учётом наследников).

### 8.7. Что такое `mutable`?

Ключевое слово — поле можно менять в `const`-методе. Для кэшей,
счётчиков вызовов.

## 9. STL

### 9.1. Разница `vector`, `deque`, `list`?

- **`vector`** — динамический массив. Быстрый доступ, добавление в конец.
- **`deque`** — двусторонняя очередь. Быстро с обоих концов.
- **`list`** — двусвязный список. Быстрые вставки в середину.

### 9.2. Что такое итератор?

«Указатель» на элемент контейнера. `begin()`, `end()`, `++`, `*`.
Категории: random access, bidirectional, forward.

### 9.3. `map` vs `unordered_map`?

- `map` — дерево, O(log n), отсортирован.
- `unordered_map` — хеш-таблица, O(1) в среднем, порядок не определён.

### 9.4. Что такое `set`?

Множество уникальных элементов, отсортировано.

### 9.5. Что делает `std::sort`?

Сортирует диапазон за O(n log n). **Не устойчивая**.
Для устойчивости — `stable_sort`.

### 9.6. Что такое компаратор?

Функция сравнения для `sort` и др. Должна быть **строгим слабым порядком**:
`cmp(a, a) == false`. Иначе UB.

### 9.7. Что такое лямбда?

Анонимная функция:

```cpp
[](int x) { return x * 2; }
```

Захват: `[x]` — по значению, `[&x]` — по ссылке, `[=]` / `[&]` — всё.

### 9.8. Что такое ranges (C++20)?

Новый способ работы с последовательностями: без `begin`/`end`,
ленивые views (`filter`, `transform`, `take`).

### 9.9. `size` vs `capacity` у `vector`?

- **`size`** — сколько элементов.
- **`capacity`** — сколько влезет без перевыделения.

`capacity` растёт **удвоением**: 1, 2, 4, 8...

## 10. Исключения и RAII

### 10.1. Что такое исключение?

Объект, описывающий ошибку. `throw` — выброс, `try`/`catch` — перехват.

### 10.2. Иерархия исключений?

`std::exception` — базовый. Наследники: `runtime_error`, `logic_error`,
`invalid_argument`, `out_of_range`, `bad_alloc`.

### 10.3. Порядок `catch`?

От **частных** к **общим**. `catch (...)` — последний.

### 10.4. Что такое RAII?

**Resource Acquisition Is Initialization.** Ресурс захватывается
в конструкторе, освобождается в деструкторе. Гарантирует освобождение
даже при исключении.

### 10.5. Что такое `noexcept`?

Обещание, что функция не бросает. Компилятор оптимизирует.
Если бросит — `std::terminate`.

### 10.6. Исключения vs `std::expected`?

- **Исключения** — для исключительных ситуаций.
- **`std::expected<T, E>`** (C++23) — для ожидаемых ошибок (парсинг, поиск).

### 10.7. Что делать, если исключение в деструкторе?

**Ловить внутри** и не пробрасывать. Деструкторы — `noexcept`.
Иначе — `std::terminate`.

## Мини-шпаргалка: ключевые правила

| Правило | Суть |
|---|---|
| RAII | Ресурс — в конструкторе, освобождение — в деструкторе |
| Правило нуля | Не управляй ресурсами вручную → используй `vector`, `unique_ptr` |
| Правило пяти | Если есть деструктор/копирование — определи все пять |
| Виртуальный деструктор | В любом полиморфном базовом классе |
| `override` | Всегда при переопределении |
| `explicit` | Конструкторы с одним параметром |
| `noexcept` | На move-операциях обязательно |
| «is-a» vs «has-a» | Наследование vs композиция |
| Компаратор | Строгий `<`, не `<=` |
| `unordered_*` | Когда порядок не важен — быстрее |
