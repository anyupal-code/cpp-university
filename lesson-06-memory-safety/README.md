# Урок 6. Висячие указатели, утечки. Ссылки. Умные указатели (кратко)

## Цель

Понять, какие ошибки возникают при ручном управлении памятью,
и научиться их избегать: ссылки, `unique_ptr`, `shared_ptr`, RAII.

## Ключевые понятия

- **`new` / `delete`** — ручное выделение и освобождение памяти.
- **Висячий указатель (dangling)** — указывает на освобождённую память.
- **Утечка памяти (leak)** — память выделена, но не освобождена.
- **RAII** — «захват ресурса есть инициализация»: владение через объект.
- **Ссылка** — псевдоним переменной, `int&`.
- **Умный указатель** — объект, владеющий памятью и автоматически её
  освобождающий: `unique_ptr`, `shared_ptr`.

---

## 1. `new` и `delete`

**Выделение:**

```cpp
int* p = new int;         // один int, не инициализирован
*p = 42;

int* q = new int(10);     // один int со значением 10

int* arr = new int[5];    // массив из 5 int
```

**Освобождение:**

```cpp
delete p;                 // для одиночного
delete[] arr;             // для массива
```

**Правила:**

- Каждому `new` — свой `delete`.
- `new[]` — только с `delete[]`.
- `delete` дважды — UB.
- После `delete` указатель лучше обнулить: `p = nullptr;`.

---

## 2. Висячий указатель

Указатель, который **указывает на освобождённую память**.

```cpp
int* p = new int(42);
delete p;

*p = 10;    // UB: p уже «висит»
```

**Откуда берётся:**

1. **После `delete`** — указатель не обнулили.
2. **Указатель на локальную переменную** из функции:
   ```cpp
   int* bad() {
       int x = 5;
       return &x;   // x умрёт после return
   }
   ```
3. **Указатель на элемент удалённого контейнера**:
   ```cpp
   std::vector<int> v = {1, 2, 3};
   int* p = &v[0];
   v.push_back(4);   // может перевыделить память — p «висит»
   ```

**Как избежать:**

- После `delete` — `p = nullptr;`.
- Не возвращать указатели на локальные переменные.
- Использовать **умные указатели** и контейнеры — они сами управляют
  памятью.

---

## 3. Утечка памяти

Память выделена через `new`, но `delete` не вызван.

```cpp
void leak() {
    int* p = new int(42);
    // забыли delete p
}

int main() {
    for (int i = 0; i < 1000000; ++i) {
        leak();   // 4 МБ утекает на каждом вызове
    }
}
```

**Последствия:**

- Программа растёт в памяти.
- При долгой работе — «съедает» всю память.
- В маленьких учебных программах не заметно, в больших — критично.

**Как избежать:**

- Правило **RAII**: владение памятью через объект.
- Используйте `unique_ptr` / `shared_ptr`.
- Используйте контейнеры (`vector`, `string`) — они сами чистят.
- **Инструменты:** `valgrind`, sanitizers (`-fsanitize=address`).

---

## 4. Двойное освобождение (double free)

```cpp
int* p = new int(42);
delete p;
delete p;    // UB: двойное освобождение
```

**Что произойдёт:** программа может упасть, испортить память
или (реже) молча продолжить.

**Как избежать:**

- После `delete` — сразу `p = nullptr;`.
  `delete nullptr` — безопасно, ничего не делает.

## 5. Ссылки

**Ссылка** — псевдоним переменной. Работает как оригинал.

```cpp
int x = 5;
int& ref = x;     // ref — псевдоним x

ref = 10;         // x тоже станет 10
std::cout << x << "\n";   // 10
```

**Отличия от указателей:**

| Свойство | Указатель | Ссылка |
|---|---|---|
| Может быть `nullptr` | да | нет |
| Можно перевести на другой объект | да | нет |
| Синтаксис | `*p`, `p->` | как обычная переменная |
| Требует инициализации | нет | да |

**Когда использовать:**

- **Ссылки** — для параметров и возвращаемых значений,
  если не нужно «ничего не передавать».
- **Указатели** — если нужно `nullptr`, арифметика, C-API.

**Пример:**

```cpp
void inc(int& x) { ++x; }      // ссылка
void inc(int* p) { ++(*p); }   // указатель

int a = 5;
inc(a);        // ссылка — проще
inc(&a);       // указатель — с &
```

## 6. Умные указатели: кратко

**Подробно — в уроке 14.** Здесь — идея.

### `std::unique_ptr`

**Единственный владелец.** Нельзя копировать, только перемещать.

```cpp
#include <memory>

std::unique_ptr<int> p = std::make_unique<int>(42);
std::cout << *p << "\n";       // 42

// delete происходит автоматически при выходе из области видимости
```

### `std::shared_ptr`

**Общий владелец.** Счётчик ссылок: объект удаляется, когда счётчик = 0.

```cpp
std::shared_ptr<int> a = std::make_shared<int>(42);
std::shared_ptr<int> b = a;    // теперь два владельца

std::cout << a.use_count() << "\n";   // 2

b.reset();                     // счётчик = 1
// когда a выйдет из области видимости — память освободится
```

### `std::weak_ptr`

**Слабая ссылка.** Не увеличивает счётчик. Для наблюдения без владения.

```cpp
std::weak_ptr<int> w = a;
if (auto sp = w.lock()) {
    std::cout << *sp << "\n";   // ок, объект ещё жив
}
```

### RAII

**Идиома:** ресурс (память, файл, сокет) захватывается в конструкторе
объекта и освобождается в деструкторе.

- `unique_ptr` — RAII для памяти.
- `std::ifstream` — RAII для файлов.
- `std::lock_guard` — RAII для мьютексов.

**Правило:** используйте RAII вместо ручного `new` / `delete`.

## 7. Что использовать в современном C++

**Забудьте про `new` / `delete` в обычном коде.**

| Задача | Чем заменить |
|---|---|
| Массив | `std::vector<T>` |
| Строка | `std::string` |
| Один объект | `std::unique_ptr<T>` или стек |
| Общий объект | `std::shared_ptr<T>` |
| Файл | `std::ifstream`, `std::ofstream` |

**Правило:** если пишешь `new` — подумай, зачем. В 99% случаев
есть более безопасная альтернатива.

## 8. Типичные задачи

### Безопасный обмен через ссылки

```cpp
void swap(int& a, int& b) {
    int t = a;
    a = b;
    b = t;
}
```

### Возврат ссылки на элемент контейнера

```cpp
std::string& first(std::vector<std::string>& v) {
    return v[0];   // ок, пока v жив
}
```

### unique_ptr в функции

```cpp
std::unique_ptr<int> make_int(int value) {
    return std::make_unique<int>(value);
}
```

## 9. Частые ошибки

- **Забыли `delete`** — утечка.
- **Забыли `delete[]`** для массива — частичное освобождение / UB.
- **Двойный `delete`** — UB.
- **Разыменование висячего указателя** — UB.
- **`delete` не той памяти** (стек vs куча) — UB.
- **Смешивание `new` с `delete[]`** или наоборот — UB.
- **Возврат ссылки на локальную переменную** — висячая ссылка.
- **Проверка ссылки на `nullptr`** — нельзя, ссылка всегда «валидна».
