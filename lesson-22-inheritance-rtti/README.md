# Урок 22. Наследование: практика, RTTI, `static_cast` / `dynamic_cast`

## Цель

Освоить полиморфизм через виртуальные функции, безопасное приведение
типов вниз по иерархии и RTTI — определение типа во время выполнения.

## Ключевые понятия

- **Виртуальная функция** — вызывается по фактическому типу объекта.
- **vtable** — таблица виртуальных методов.
- **`override`** — контроль переопределения.
- **`final`** — запрет наследования или переопределения.
- **Срезка объектов** — потеря части объекта при копировании.
- **`static_cast`** — приведение без проверки.
- **`dynamic_cast`** — безопасное приведение вниз (нужен `virtual`).
- **RTTI** — Run-Time Type Information. `typeid`.

---

## 1. Виртуальные функции

**Ключевое отличие C++:** методы **не виртуальные** по умолчанию.

```cpp
class Animal {
public:
    virtual void voice() const {     // ← virtual
        std::cout << "...\n";
    }
};

class Dog : public Animal {
public:
    void voice() const override {    // ← override
        std::cout << "Гав\n";
    }
};
```

**Что даёт `virtual`:**

```cpp
Dog d;
Animal* p = &d;
p->voice();   // "Гав" — вызван по фактическому типу
```

Без `virtual` вызвался бы `Animal::voice` — по типу указателя.

**Правила:**

- Виртуальная функция — **в базовом классе**.
- Наследник переопределяет через `override`.
- Вызов идёт **по фактическому типу** объекта (динамическое связывание).
- Работает только через **указатель или ссылку**.

---

## 2. Как это работает — vtable

**vtable** — таблица виртуальных методов. По одной на класс.

- У каждого объекта с виртуальными методами есть **скрытый указатель на vtable**.
- При вызове виртуальной функции компилятор:
  1. Берёт vtable по указателю объекта.
  2. Находит в ней нужный метод.
  3. Вызывает.

**Следствия:**

- Виртуальный вызов **чуть дороже** обычного (одна разыменовка).
- Внутри конструктора/деструктора виртуальность **не работает полностью**
  (vtable строится по частям).
- Размер объекта **увеличивается** на размер указателя.

**В обычном коде** об этом не думаешь — компилятор и процессор справляются.
Помни только, что **виртуальные вызовы не бесплатны**.

## 3. `override` и `final`

**`override`** — компилятор проверит, что метод действительно
переопределяет виртуальный из родителя.

```cpp
class Dog : public Animal {
public:
    void voice() const override;   // ошибка компиляции, если в Animal нет voice
};
```

**Правило:** **всегда пишите `override`**, если переопределяете.

**`final`** — запрет:

```cpp
class Base {
public:
    virtual void f() const;
};

class Derived : public Base {
public:
    void f() const override final;   // ← запрет переопределения дальше
};

class Third : public Derived {
public:
    void f() const override;   // ошибка: f — final
};
```

**`final` на классе** — запрет наследования:

```cpp
class NoDerive final {
    // от этого класса нельзя наследовать
};
```

**Применение:**

- Оптимизация — компилятор знает, что метод не переопределят.
- Документация — явно «здесь конец иерархии».

## 4. Срезка объектов (slicing)

**Проблема:** при копировании наследника в переменную базового типа
**теряется** часть наследника.

```cpp
Dog d("Бим");

Animal a = d;    // СРЕЗКА: копируется только Animal-часть

Animal* p = &d;  // ок — указатель
Animal& r = d;   // ок — ссылка
```

**Что теряется:**

- Поля наследника.
- Виртуальность — `a.voice()` вызовет `Animal::voice`.

**Правило:** **не копируйте** полиморфные объекты по значению.
Используйте **указатели или ссылки**.

**Правильно:**

```cpp
void process(const Animal& a) {    // ссылка — без срезки
    a.voice();
}

process(d);   // ок
```

## 5. `dynamic_cast`

**Приведение вниз** по иерархии **с проверкой**. Требует `virtual`
в базовом классе.

```cpp
Animal* p = new Dog("Бим");

Dog* d = dynamic_cast<Dog*>(p);
if (d != nullptr) {
    d->bark();    // ок, если p — действительно Dog
} else {
    std::cout << "не Dog\n";
}
```

**Что делает:**

- Проверяет **фактический** тип во время выполнения.
- Если приведение удачно — возвращает указатель.
- Если нет — **`nullptr`** (для указателей) или **`std::bad_cast`**
  (для ссылок).

**Приведение ссылок:**

```cpp
try {
    Dog& d = dynamic_cast<Dog&>(*p);
    d.bark();
} catch (const std::bad_cast&) {
    std::cout << "не Dog\n";
}
```

**Когда использовать:**

- Наследник имеет **дополнительный** интерфейс, не входящий в базовый.
- Проверка типа перед операцией.

**Когда не использовать:**

- Если можно сделать метод **виртуальным** — делайте. Это чище.
- В горячем коде — `dynamic_cast` медленный.

---

## 6. `static_cast`

**Приведение без проверки.** Компилятор доверяет тебе.

```cpp
double d = 3.14;
int i = static_cast<int>(d);      // 3

Animal* p = new Dog("Бим");
Dog* dog = static_cast<Dog*>(p);  // без проверки
```

**Что делать — решаешь ты.** Если тип неверный — **UB**.

**Когда использовать:**

- Между числами.
- Между указателями в **точно известном** типе.
- Вверх по иерархии — безопасно.
- Вниз — только если точно уверен.

**Разница:**

| | `static_cast` | `dynamic_cast` |
|---|---|---|
| Проверка во время выполнения | нет | да |
| Скорость | быстрый | медленнее |
| Требует `virtual` | нет | да |
| Безопасность | на совести программиста | безопасный |

## 7. RTTI — `typeid`

**RTTI** — информация о типе во время выполнения.

```cpp
#include <typeinfo>

Animal* p = new Dog("Бим");

std::cout << typeid(*p).name() << "\n";      // "Dog" (или искажённое имя)
std::cout << typeid(*p).hash_code() << "\n";

if (typeid(*p) == typeid(Dog)) {
    std::cout << "это Dog\n";
}
```

**Что нужно:**

- `virtual` в базовом классе — иначе `typeid(*p)` вернёт тип указателя.
- `#include <typeinfo>`.

**Сравнение типов:**

- `typeid(a) == typeid(b)` — **одинаковые типы**.
- Не работает для «является ли наследником» — для этого `dynamic_cast`.

**Осторожно:** `typeid(*p)` **разыменовывает** `p`. Если `p == nullptr` —
**исключение** `std::bad_typeid`.

**Применение:**

- Отладка — «что за объект».
- Логирование.
- Хеш-ключи по типу.

## 8. Полиморфные контейнеры

Хранить разные типы вместе через `unique_ptr<Base>`:

```cpp
std::vector<std::unique_ptr<Shape>> shapes;

shapes.push_back(std::make_unique<Circle>(5));
shapes.push_back(std::make_unique<Rect>(3, 4));

for (const auto& s : shapes) {
    std::cout << s->area() << "\n";    // виртуальный вызов
}
```

**Правила:**

- Деструктор базового класса — **`virtual`**.
- Хранить через **указатель** (обычно `unique_ptr`), не по значению.
- Контейнер **не копируется** — move-only.

## 9. Типичные задачи

### Полиморфная обработка

```cpp
void process(const Shape& s) {
    std::cout << s.name() << ": " << s.area() << "\n";
}

for (const auto& s : shapes) {
    process(*s);
}
```

### Проверка типа и специфичное действие

```cpp
for (const auto& s : shapes) {
    if (auto* c = dynamic_cast<Circle*>(s.get())) {
        std::cout << "Радиус: " << c->radius() << "\n";
    }
}
```

### Группировка по типу

```cpp
std::unordered_map<std::string, int> by_type;
for (const auto& s : shapes) {
    ++by_type[typeid(*s).name()];
}
```

---

## 10. Частые ошибки

- **Забыли `virtual`** — нет полиморфизма.
- **Забыли `virtual` деструктор** — утечка при удалении через базу.
- **Срезка** — копирование наследника в переменную базы.
- **`dynamic_cast` без `virtual`** — ошибка компиляции.
- **`static_cast` вниз без проверки** — UB при неверном типе.
- **`typeid(*p)` при `p == nullptr`** — исключение.
- **Виртуальный вызов в конструкторе/деструкторе** — не работает как ожидается.
- **Изменение сигнатуры при `override`** — компилятор поймает, если есть `override`.
