# Урок 17. Контейнеры последовательные: практика

## Цель

Научиться **выбирать контейнер под задачу**, а не использовать
`vector` по умолчанию везде. Разобрать 5 типичных сценариев.

## Формат урока

Каждая задача:

1. **Условие.**
2. **Идея решения.**
3. **Почему такой контейнер** (сравнение с альтернативами).
4. **Код.**
5. **Тесты.**

## Задача 1. Кольцевой буфер

**Условие.** Реализовать буфер фиксированного размера `N`,
в который можно добавлять элементы. При переполнении старые
элементы **вытесняются** новыми. Вывести содержимое в порядке
добавления.

**Идея.** Буфер ведёт себя как **очередь фиксированной длины**:
- добавляем в конец,
- если размер > N — убираем с начала.

**Почему `deque`:**
- Нужны операции **с обоих концов** (`push_back`, `pop_front`).
- `vector` требует O(n) для удаления с начала — плохо.
- `list` работает, но **медленнее** из-за аллокаций.
- `deque` — оптимум: O(1) с обеих сторон + доступ по индексу.

**Тест:**

```
N = 3
push 1, 2, 3 → [1, 2, 3]
push 4       → [2, 3, 4]
push 5       → [3, 4, 5]
```

**Разбор** — в [task_ring_buffer.cpp](task_ring_buffer.cpp).

## Задача 2. Стек отмен (undo)

**Условие.** Реализовать стек операций с ограничением:
хранится последних `N` действий. При добавлении нового
самое старое удаляется. Операция `undo` возвращает последнее действие
и удаляет его.

**Идея.** Стек **фиксированной длины**:
- `push` — добавить в конец,
- `undo` — удалить с конца,
- если размер > N — удалить **с начала**.

**Почему `deque`:**
- С одной стороны — стандартный стек (`push_back`, `pop_back`).
- С другой — ограничение сверху (`pop_front`).
- `vector` неудобен: удаление с начала — O(n).

**Альтернатива:** `std::stack` **не подходит** — нельзя ограничить размер
без ручной проверки, и нет доступа к нижнему элементу.

**Разбор** — в [task_undo.cpp](task_undo.cpp).

## Задача 3. Скользящее окно: максимум в окне

**Условие.** Дан массив чисел и размер окна `K`. Для каждой позиции
`i` (начиная с `K-1`) вывести **максимум** в окне `[i-K+1, i]`.

**Пример:**

```
arr = [1, 3, -1, -3, 5, 3, 6, 7]
K = 3
Вывод: [3, 3, 5, 5, 6, 7]
```

**Наивное решение:** для каждой позиции пробегать окно — O(n·K).

**Эффективное:** **монотонная очередь** на `deque` — O(n).

**Идея:**

- В `deque` храним **индексы** элементов в порядке убывания значений.
- Перед добавлением нового индекса — выкидываем с конца все
  элементы **меньше** нового.
- Выкидываем с начала индексы, которые **вышли из окна**.
- Первый элемент `deque` — максимум окна.

**Почему `deque`:**
- Нужны операции с обоих концов.
- `vector` тоже возможен, но `deque` удобнее семантически.

**Разбор** — в [task_sliding_window.cpp](task_sliding_window.cpp).

## Задача 4. Топ-K элементов

**Условие.** Дан массив. Найти `K` наибольших элементов.

**Идея 1 (простая):** отсортировать и взять последние K — O(n log n).

**Идея 2 (быстрая):** `std::partial_sort` — O(n log K).

**Идея 3 (поток):** `std::priority_queue` — O(n log K), работает
при потоковом вводе, когда нельзя хранить весь массив.

**Почему `vector`:**
- Данные в памяти, произвольный доступ.
- `partial_sort` работает **на месте**, ничего дополнительного не нужно.

**Разбор** — в [task_top_k.cpp](task_top_k.cpp).

## Задача 5. Частоты слов

**Условие.** Дан текст. Посчитать, сколько раз встречается каждое слово.

**Идея.** Пока используем **пару `vector<...>`**:

- `vector<string>` — уникальные слова,
- `vector<int>` — их частоты.

**Почему не `map` сейчас:**
- `map` будет в следующем уроке — там эта задача решается в 3 строки.
- Здесь — показать «ручной» подход.

**Что важно:** выбирать между «вектор пар» и «два параллельных
вектора». Первое чище.

**Разбор** — в [task_word_freq.cpp](task_word_freq.cpp).

## Как выбирать контейнер

| Что нужно | Контейнер |
|---|---|
| Доступ по индексу, добавление в конец | `vector` |
| Добавление/удаление с обоих концов | `deque` |
| Частые вставки/удаления в середине | `list` |
| Фиксированный размер, методы STL | `array` |
| LIFO | `vector` / `std::stack` |
| FIFO | `deque` / `std::queue` |

**Правило:** если сомневаешься — `vector`. Он в 90% случаев выигрывает.

**Правило-исключение:** если нужны **частые операции с началом
контейнера** — `deque`.
