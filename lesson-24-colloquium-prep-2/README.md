# Урок 24. Подготовка к коллоквиуму (продолжение): практика

## Цель

Закрепить ООП на практике: спроектировать иерархии, реализовать
правило пяти, использовать полиморфизм и умные указатели в реальных
сценариях.

## Формат урока

Пять **самостоятельных задач** — мини-проектов, типичных для коллоквиума.
Каждая — с полным разбором.

---

## Задача 1. Иерархия фигур

**Условие.** Спроектировать:

- `Shape` — абстрактный: `area()`, `perimeter()`, `name()`.
- `Circle`, `Rectangle`, `Triangle` — конкретные наследники.
- Свойства: только для чтения.
- Функция `describe(const Shape&)` — печатает имя, площадь, периметр.
- Полиморфная коллекция `vector<unique_ptr<Shape>>`.

**Что тренирует:**

- Абстрактный класс + чистые виртуальные функции.
- `virtual` деструктор.
- Полиморфная коллекция через `unique_ptr`.
- Свойства только для чтения.

**Разбор** — в [practice_shapes.cpp](practice_shapes.cpp).

---

## Задача 2. Класс `Buffer` с правилом пяти

**Условие.** Реализовать класс `Buffer`:

- Владеет массивом `int`.
- Размер задаётся в конструкторе.
- Копирование — глубокое.
- Move — перенос владения.
- `operator[]` — доступ с проверкой границ.

**Что тренирует:**

- Правило пяти во всех деталях.
- RAII.
- `operator[]` с проверкой.
- Move-семантика.

**Разбор** — в [practice_buffer.cpp](practice_buffer.cpp).

---

## Задача 3. Реестр объектов (Registry)

**Условие.** Реализовать «реестр»:

- Хранит объекты по строковому ключу.
- `add(key, obj)` — добавить.
- `get(key)` — получить по ключу или `nullptr`.
- `remove(key)` — удалить.
- `size()` — количество.
- Хранение через `unique_ptr<Shape>`.

**Что тренирует:**

- `unordered_map<string, unique_ptr<Shape>>`.
- Владение через `unique_ptr`.
- Работа с `find` без создания элементов.
- Move-only контейнеры.

**Разбор** — в [practice_registry.cpp](practice_registry.cpp).

---

## Задача 4. Наблюдатель (Observer, упрощённый)

**Условие.** Реализовать простую схему «издатель — подписчики»:

- `Publisher` — хранит значение, при изменении уведомляет.
- `Observer` — интерфейс с `on_update(int)`.
- Издатель хранит список подписчиков через `weak_ptr`.

**Что тренирует:**

- Интерфейсы (абстрактные классы).
- `weak_ptr` и `lock()`.
- Управление временем жизни.
- Уведомление всех подписчиков.

**Разбор** — в [practice_observer.cpp](practice_observer.cpp).

## Задача 5. Тренировочные вопросы

**Условие.** Разбор 10 типичных вопросов коллоквиума с кодом-примером
на каждый:

1. Порядок вызова конструкторов и деструкторов.
2. Зачем виртуальный деструктор.
3. Что такое срезка.
4. Разница `override` и перегрузки.
5. Правило пяти — зачем каждое.
6. `unique_ptr` vs `shared_ptr` — когда что.
7. Что такое `weak_ptr` и зачем.
8. `dynamic_cast` vs `static_cast`.
9. Что такое `const`-метод.
10. Что такое RAII.

**Разбор** — в [practice_questions.cpp](practice_questions.cpp).

## Как готовиться

1. **Прогони все 5 задач.** Убедись, что понимаешь код.
2. **Перепиши задачи с нуля.** Без подглядывания.
3. **Прорешай вопросы** из задачи 5 — отвечай вслух.
4. **Пробуй менять код:** добавь новый класс, измени контейнер,
   сделай move-only.

## Что спросят обязательно

- **«Зачем `virtual` деструктор?»** — корректное удаление наследника
  через базовый указатель.
- **«Правило пяти — почему каждое?»** — контроль над копированием
  и перемещением при ручном управлении ресурсами.
- **«Чем отличается `unique_ptr` от `shared_ptr`?»** — единственный
  vs общий владелец, счётчик ссылок.
- **«Что такое срезка?»** — потеря части наследника при копировании
  в базовый тип.
- **«`override` — зачем?»** — компилятор проверит, что метод
  действительно переопределяет.
