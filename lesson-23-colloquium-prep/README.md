# Урок 23. Подготовка к коллоквиуму

## Цель

Систематизировать материал по ООП: классы, наследование, полиморфизм,
правило пяти. Разобрать типичные вопросы и ошибки.

## Темы коллоквиума

1. **Классы и объекты** — конструкторы, деструкторы, копирование.
2. **Инкапсуляция** — `public`, `protected`, `private`, свойства.
3. **Наследование** — «is-a», порядок вызова, виртуальный деструктор.
4. **Полиморфизм** — виртуальные функции, vtable, `override`.
5. **Правило пяти** — копирование, перемещение, RAII.
6. **Умные указатели** — `unique_ptr`, `shared_ptr`, `weak_ptr`.

## 1. Классы и объекты — повторение

**Что обязательно:**

- Конструктор по умолчанию: `Point() = default;`
- Конструктор с параметрами + список инициализации: `Point(int x) : x_(x) {}`
- `explicit` для конструкторов с одним параметром.
- Деструктор, если класс владеет ресурсами.

```cpp
class Point {
private:
    int x_, y_;
public:
    Point() : x_(0), y_(0) {}
    explicit Point(int x) : x_(x), y_(0) {}
    Point(int x, int y) : x_(x), y_(y) {}

    int x() const { return x_; }
    int y() const { return y_; }

    void set_x(int x) { x_ = x; }
};
```

**Что спросят:**

- «Зачем `explicit`?» — запретить неявное преобразование.
- «Что такое список инициализации?» — инициализация полей **до** тела.
- «В каком порядке инициализируются поля?» — **в порядке объявления**, не в списке.

## 2. Инкапсуляция

| Уровень | Кто видит |
|---|---|
| `public` | все |
| `protected` | класс + наследники |
| `private` | только класс |

**Правило:** поля — `private`, интерфейс — `public`,
наследникам — `protected` (если нужно).

**Геттеры/сеттеры:**

```cpp
class Person {
private:
    std::string name_;
    int age_;

public:
    const std::string& name() const { return name_; }
    void set_name(std::string n) { name_ = std::move(n); }

    int age() const { return age_; }
    void set_age(int a) {
        if (a < 0 || a > 150) throw std::invalid_argument("age");
        age_ = a;
    }
};
```

**Что спросят:**

- «Зачем геттеры, если можно сделать поле публичным?» — валидация,
  контроль, смена реализации без изменения интерфейса.
- «Что возвращать из геттера?» — `const&` для больших типов, значение для маленьких.

## 3. Наследование

```cpp
class Animal {
protected:
    std::string name_;
public:
    explicit Animal(std::string n) : name_(std::move(n)) {}
    virtual ~Animal() = default;

    virtual std::string voice() const { return "..."; }
};

class Dog : public Animal {
public:
    explicit Dog(std::string n) : Animal(std::move(n)) {}

    std::string voice() const override { return "Гав"; }
};
```

**Что спросят:**

- «Порядок вызова конструкторов?» — **Base → Derived**.
- «Порядок деструкторов?» — **Derived → Base**.
- «Зачем `virtual ~Animal()`?» — корректное удаление через базовый указатель.
- «Что такое `override`?» — проверка компилятором, что метод действительно
  переопределяет виртуальный из родителя.
- «`public` наследование — что это?» — «is-a». Публичные члены родителя
  остаются публичными.

## 4. Полиморфизм

**Виртуальная функция** — вызывается по **фактическому** типу:

```cpp
Dog d("Бим");
Animal* p = &d;
p->voice();   // "Гав" — благодаря virtual
```

**Как работает:**

- vtable — таблица виртуальных методов.
- У объекта — скрытый указатель на vtable.
- Вызов — через таблицу.

**Что спросят:**

- «Чем отличается виртуальная функция от обычной?» — вызывается по
  фактическому типу, а не по типу указателя.
- «Что такое vtable?» — таблица виртуальных методов.
- «Где работает полиморфизм?» — только через **указатель или ссылку**.
  По значению — срезка.
- «Что такое срезка?» — потеря части наследника при копировании в базу.
- «Зачем `final`?» — запретить переопределение или наследование.

## 5. Правило пяти

Если класс **владеет ресурсами**:

1. **Конструктор** — захват ресурса.
2. **Деструктор** — освобождение.
3. **Копирующий конструктор** — глубокое копирование.
4. **Копирующее присваивание** — deep copy + самоприсваивание.
5. **Move-конструктор** — «украсть» ресурсы. `noexcept`.
6. **Move-присваивание** — то же. `noexcept`.

```cpp
class Buffer {
    int* data_;
    std::size_t size_;

public:
    explicit Buffer(std::size_t n) : data_(new int[n]), size_(n) {}
    ~Buffer() { delete[] data_; }

    Buffer(const Buffer& o) : data_(new int[o.size_]), size_(o.size_) {
        std::copy(o.data_, o.data_ + size_, data_);
    }

    Buffer& operator=(const Buffer& o) {
        if (this != &o) {
            delete[] data_;
            size_ = o.size_;
            data_ = new int[size_];
            std::copy(o.data_, o.data_ + size_, data_);
        }
        return *this;
    }

    Buffer(Buffer&& o) noexcept : data_(o.data_), size_(o.size_) {
        o.data_ = nullptr;
        o.size_ = 0;
    }

    Buffer& operator=(Buffer&& o) noexcept {
        if (this != &o) {
            delete[] data_;
            data_ = o.data_;
            size_ = o.size_;
            o.data_ = nullptr;
            o.size_ = 0;
        }
        return *this;
    }
};
```

**Правило нуля** (современный подход): не управляй ресурсами вручную —
используй `vector`, `string`, `unique_ptr`. Тогда всё работает **само**.

**Что спросят:**

- «Зачем `noexcept` на move-операциях?» — `vector` использует move
  только если он `noexcept`.
- «Что такое правило трёх/пяти/нуля?» — см. выше.
- «Зачем проверка `this != &o`?» — самоприсваивание.

## 6. Умные указатели

| Указатель | Когда использовать |
|---|---|
| `unique_ptr` | один владелец |
| `shared_ptr` | несколько владельцев |
| `weak_ptr` | наблюдение без владения |

```cpp
auto p = std::make_unique<Shape>(...);
auto s = std::make_shared<Shape>(...);
std::weak_ptr<Shape> w = s;
```

**Что спросят:**

- «Когда `unique_ptr`, когда `shared_ptr`?» — один владелец vs несколько.
- «Что такое `weak_ptr`?» — слабая ссылка, не увеличивает счётчик.
- «Зачем `weak_ptr`?» — разорвать циклические ссылки, наблюдение.
- «Что такое циклическая ссылка?» — два `shared_ptr` друг на друга → утечка.

## 7. Типичные ошибки

- **Не виртуальный деструктор** при удалении через базу — утечка.
- **Срезка** — копирование полиморфного объекта по значению.
- **`=` вместо `==`** в условиях.
- **Забыли `override`** — переопределение без проверки.
- **Возврат ссылки на локальную переменную** — UB.
- **Использование после `std::move`** — состояние неопределено.
- **`delete` дважды** — UB.
- **`shared_ptr` цикл** — утечка.
- **Компаратор с `<=`** — UB в `sort`.
- **Порядок `catch`** от общего к частному — частные не сработают.
